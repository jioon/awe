# 生产工程路线（不是实验性原型路线）

## 产品目标

数据团队通过正常的数仓开发流程交付正式的语义、计算、工程和验证契约。AWE 把以表、SQL、作业、报表为中心的实现，连接到不可变实体、关系、契约与能力；生产、消费和验证共享同一发布定义，供 BI、算法、个人/平台 Agent 使用，并从真实任务失败推动数仓改进。

目标至少完成 F3 的生产、消费、验证和修复回放闭环，再扩展复杂分析、算法特征与安全生产操作。Agent 可在 AWE 外保存自己的 Skills 和定制工作流，通过 AWE 的稳定 API 组合受控能力；这些流程不改变服务器的类型、版本、授权和证据边界。

## F0–F6 阶段和可解决范围

| 阶段 | 工程内容 | 能解决的真实问题 | 退出标准 |
|---|---|---|---|
| F0 工程基础 | 完整架构约束；Java 核心类型/关系/时间/结果契约；Maven CI；测试矩阵 | 稳定边界，避免后续把 LLM/目录猜测误当正确性 | 契约测试与 CI 通过，ADR 经业务问题检验 |
| F1 模型生产 | PostgreSQL Registry、不可变版本、Authoring API、Web 编辑/审核、真实 Hive/BI/知识库源绑定、漂移检查 | 业务数仓团队可维护、发布一个真实模型，知道何为权威 | 一个真实领域端到端完成建模发布；可追溯审核和差异 |
| F2 受控问数 | Hybrid Resolver、候选消歧、Semantic IR/Compiler、BI 适配、MCP/REST、权限、证据 | 可信指标/维度查询、黑话、歧义正确澄清、非法查询拒绝 | 指标结果与权威 BI 对账；边界/权限负例全部通过 |
| F3 数仓闭环 | Dataset/Pipeline/血缘/质量、有限推导规划、变更兼容、在线评测和 Gap 工作流 | 现有数据能否推导、任务为何异常、加工变更影响谁 | 真实 DWD/DWS 变更可发现并验收；Gap 修复回放闭环 |
| F4 复杂分析 | 多跳 Join、桥接、扇出、SCD、比率/半可加、窗口、缓存/物化 | 复杂数仓的安全通用语义计算 | 每类复杂语义具代表性业务用例和非法反例 |
| F5 算法用数 | Profile/Feature、point-in-time、available-at、TTL、离线/在线/训练一致性 | 可查询历史可信特征并避免信息泄露 | 训练时点/回补/在线一致性测试通过 |
| F6 安全生产操作 | 任务/模型 Action、审批、幂等、回滚/补偿、后验证 | 安全回补、任务重跑、模型发布与恢复 | 完成授权安全审查、dry-run、失败恢复和审计 |

**F1 并非另做硬编码演示：必须真实连接内部资产来源并支持持久化与页面发布。**
F2 不接伪数据充当真实结果；外部系统尚未配置时必须明确 DISABLED / NOT_CONFIGURED。

## 当前进度与验收边界

- F0：基础契约与七类 Java 元模型、架构约束和正反测试已经落地。
- F1a：PostgreSQL 持久化、Authoring API、独立审核、不可变发布和 Web 工作台已经落地。早期宽松 JSON 与弱来源绑定的缺口由 F1b 补齐，不把旧实现的发布状态追认为已验证来源。
- F1b 已合并：七类模型使用同一严格 v2 文档进入 Registry；精确依赖版本/Hash、模型兼容性检查、Hive/BI 元数据网关 SPI、不可变来源观测、发布时重读与物理契约/漂移 Gate、失败证明、问题候选和依赖影响进入同一工作流。来源指纹与候选模型契约分开记录，发布回滚保留检查证明。未配置的来源明确返回 `NOT_CONFIGURED`；本地协议测试不宣称已接通真实企业来源。
- F1 尚未达到完整退出标准：真实业务域和 Hive/BI 权威来源接入与负责人验收仍需完成。当前列/声明粒度/时间元数据比较不证明行级质量、真实数值口径或业务真值。
- 本增量交付首个 F3 执行纵切面：只读数据检查固定 Dataset/Contract 的 Release ID 与 Hash，经新鲜来源 Gate 后，通过运维映射的真实 PostgreSQL 关系执行注册的粒度/时间规则；失败生成不可变证据与运行缺口，外部修复真实数据后按原契约重新执行并验证关闭。空关系、超限与缺少配置不能产生伪造通过。
- F2 尚未实现完整语义查询链；F3 也未整体完成：仍需真实生产 DDL/SQL/作业发布 Gate、原生 Hive/Spark/BI 适配、源端二次授权、质量/血缘/影响回归和企业任务修复流程。本次只读检查不是任意 SQL 执行、调度或数仓写入能力。

设计与取舍见 [ADR-013：类型化发布与来源 Gate](architecture/adr-013-typed-registry-and-source-gates.md) 和 [ADR-014：Agent Skills 与数据验证、修复回放](architecture/adr-014-agent-skills-and-data-verification-loop.md)。后续继续在本 Registry、内核和运行记录上接入真实业务领域的生产/消费路径，不重新建立独立原型。

## 下一步生产验收任务

1. 接入真实业务域与权威 Hive/BI 来源，确认已有元数据网关和只读验证关系的映射及业务负责人。
2. 将精确版本模型与契约接入真实 DDL/SQL/作业开发和发布流程，保留编译/执行使用的 Release/Hash。
3. 增加实际引擎的数据适配与受控语义消费，覆盖源端身份、行列权限、超时和资源预算。
4. 将失败证明送入现有质量/调度/开发流程，修复真实数仓后回放原任务及受影响的下游回归。
5. 以 S01—S06、S10—S12 和 S19 的真实任务验收生产、消费、验证闭环，再开放更广泛的 Resolver/MCP 与自定义 Agent Skills。

## 仍需同现有平台明确的接口问题

- BI 指标平台是否存储权威的粒度、聚合、维度、过滤与时间规则？只有 SQL 还是支持语义请求？
- 真实业务对象身份如何映射？用户/设备/游客、账号变更与历史版本是什么？
- 数仓数据的事件时间/服务端时间/分区/水位如何定义，哪些情况下数据可以回补？
- 现有血缘和 DDL/SQL 变化能否通过事件/接口获取？是否有源码版本？
- 数据权限在哪些系统判定？有哪些行列、PII、地域和跨域组合限制？
- 质量数据源与可用性/可信证据如何接入？接口失败时应如何回退？
- Query Budget、执行超时、并发、审计/脱敏等要求是什么？

首轮开发无需用户提供任何数据库密码；配置采用环境变量/密钥引用。正式实现不应把连接串写在仓库中。

## 每个增量的 Definition of Done

源码、自动化测试、正反案例、数据库迁移（如涉及）、观察与审计、接口契约、Web 可视化（如涉及）、文档、真实业务负责人验收及变更回滚方案。CI 绿是最低标准，不能代替业务任务验收。
