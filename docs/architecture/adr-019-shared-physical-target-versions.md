# ADR-019：共享物理目标的版本、写入代次与当前实现证明

- 状态：已接受；承接 ADR-018 的 M2 准入与 M1 逻辑目标消费
- 问题：不同 Pipeline 可以写同一个物理目标，单个 Pipeline 的 CAS 不能防止另一个 Pipeline 的迟到发布覆盖；相同 Schema 也不能证明仍运行相同语义。

## 决策与职责

AWE 继续约束数据契约、授权与证据；部署平台继续执行数据写入和版本提交。两者使用物理目标版本向量，不能用 Pipeline 自身版本代替共享目标的版本。

1. 网关生产协议升级为 v2。真实基线观测覆盖本次**全部**物理目标，每项包含 targetKey、revision、consumptionId、intentId，环境在外层明确固定。回归证明绑定整个向量的规范 Hash。
2. AWE 对同环境/目标按统一顺序加事务锁，追加单调写意图。V9 记录不可更新/删除；意图 ID 是精确十进制字符串，不以时间戳、UUID 排序或回调先后来决定所有者。多个 Pipeline/实例共享同一 Registry 权威。
3. 授权绑定完整目标基线与新意图。平台须在写任何目标前原子校验全部目标版本和代次；数据、目标所有者、部署幂等记录与新版本必须在同一事务/等效原子提交机制内生效。任一目标冲突或写入失败，不能留下部分目标已发布。
4. 实际部署观测分别提供历史 targetRevisions 和实时 currentTargets。历史部署确实完成不代表仍是当前实现。AWE 检查它们与授权、模型、制品、环境、消费及运行引用完全一致。
5. 逻辑目标每次用于来源 Gate 或查询，均重新查询可信平台活动版本，不对正向证明做缓存。原生只读事务前后继续复检；发生代次变化时抑制结果，不能以历史 PASSED 和相同 Schema 返回错误语义的数据。
6. 旧回调只追加自己 consumption 的审计；它不能覆盖新所有者的状态，也不能让新版本失效。当前绑定使用确切环境、单调意图和本消费的最新观测。

## 标识、兼容与失败

同一物理资源必须使用规范资产标识并由同一写入权威管理；环境标签本身不隔离实际存储。同一真实表若跨环境共享写入，必须使用共同的目标治理命名空间，不能各自维护独立 owner/CAS。PostgreSQL 生产映射中，同一连接 relation 的多个外部别名将阻断相关生产目标；普通消费映射不因此改写。Hive/BI 适配器和部署平台同样须在规范资源上锁定、比较版本；不能按业务别名各自维护独立所有者。

已有七类模型、v2/v3 模型发布及其 Hash 不变。旧生产协议记录保留供审计，不自动升级成 v2 授权或当前实现证明；升级后须重新准备、验证、批准和消费。未配置平台返回 NOT_CONFIGURED；缺向量、错范围、旧协议、旧代次或不完整证明拒绝，不能静默降级。

收到确定终态后，工作台为下一次物化观测生成新请求键；网络失败使用原键/原载荷重试。页面明确区分历史重放与新观测，PASSED 只描述当次证据，不冒称当前实时有效。

## 证明边界

可信平台必须把数据改变与目标状态原子登记，包括其能够管理的旁路替换。若 DBA 或旧任务绕过平台直接改数据且不改变任何可信版本，读取 owner 状态无法发现这种同 Schema 改写；需要源端写权限、入口纳管及独立质量/对账共同约束，不能声称消除了所有线下覆写。

多目标的原子提交能力由平台提供。Hive/Spark 等不能满足此能力时，适配应拒绝此发布模式，或先形成具备原子切换语义的版本化制品；AWE 不构建跨系统事务或调度器。

## 真实验收

参考平台对 PostgreSQL 实际目标行和版本状态执行事务 CAS，按实际 relation 加锁；独立计算与回归仍使用真实 SQL。验收覆盖共享目标的交错发布、旧回调、无回调的可信状态替换、完整向量、并发意图、环境隔离、不可变证据，以及第二目标失败后的整体回滚与同消费重试。单个 Pipeline 基线、历史物化与独立数值对账继续分别记录。
