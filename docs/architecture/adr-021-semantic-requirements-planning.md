# ADR-021：结构化数据需求到受限合法计划

- 状态：已接受并实现有界工程范围
- 承接：ADR-016、ADR-018、ADR-020；M1 的正式能力裁决

## 需要闭合的断点

已有 QUERY_METRIC v2 要求消费者先选定 Function，只能调用其固定计划。这仍把一部分实现选择留在 Agent，也不能直接表达“按原指标口径，改用这些维度和筛选”。AWE 需要依据正式模型判断要求是否合法，并生成可执行、可追踪的计划；不能接受客户端自拟 SQL/IR，也不能把任意重组都当成合法指标计算。

## 请求表达语义，系统选择实现

DataTask v3 的 QUERY_METRIC 固定正式 Metric 的 Release/Hash；显式声明统计主体及其版本、单位、业务时区、时间角色、度量、分组维度、类型化维度筛选和时间范围。缺少或不匹配的语义不能靠名称相似、默认账期或 Agent 自报认证补足。它是消费协议的新版本，不是第八类元模型；已有 EXTRACT v1、QUERY_METRIC v2 及不可变发布继续有效。

系统只考虑当前主体获准调用、绑定该确切 Metric 的正式 Function。唯一合法候选形成 PLANNED；多个候选返回 AMBIGUOUS，调用方可显式固定 candidateFunction 的 Release/Hash 后重评。没有可披露候选返回 NOT_DISCLOSED；可见范围不支持该要求返回 UNSUPPORTED，两者均不证明企业不存在对应资产或能力。不自动选择最新版本。

自动候选检索最多考察 256 个可调用 Function 发布；超过预算返回 CANDIDATE_BUDGET_EXCEEDED、catalogComplete=false 和供给 UNKNOWN，不截取首项冒称唯一。显式候选可以在同一授权约束下单独核对。

## 从原输入重新计算，保留正式口径

当前支持原计划顶层 Aggregate，或只以 Field 重命名输出的 Project(Aggregate)。原 grain 必须准确对应全部聚合分组键。消费者可选择已声明度量和分组维度的子集，并对正式维度增加类型一致的比较条件。筛选放在该聚合之前，原有业务输入、固定筛选、Join、集合及时间窗口保留；不增设未经认证的关联路径。

移除维度时，从原聚合输入重新计算原 Measure。例如同一设备出现在多个应用中，城市级 COUNT_DISTINCT 必须重新对设备去重，不能把应用级去重计数相加。派生契约固定所选输出、粒度、主体、单位、身份空值和空结果政策，继续执行完整静态类型检查及实际输入字段/强制行策略检查。

要求与原正式契约完全相同时，可复用复杂原计划和原 DIRECT 实现。需要重组的复合表达式、缺少明确分组映射的计划等返回具名限制。BI DIRECT 当前不是任意计划执行器；派生后的完整契约与原契约不同就返回 EXTERNAL_DERIVATION_NOT_REGISTERED，不能调用原 BI 实现后把结果冒充新粒度。

## 评估、执行与回归是不同证据

静态评估将规范请求、当前政策、候选、诊断和计划保存到现有不可变 awe_resolution_observation。计划清单包含固定模型、来源、派生契约、强制行策略、AWE_METRIC_DERIVATION_V1、原契约 Hash、需求 Hash 和最终 planHash；没有更改旧发布或旧回归 Hash。

PLANNED 的 readiness 始终 UNKNOWN。评估不读取结果，不建立当前来源、账期完整或数值正确证明，也不是执行许可。实际调用仍经当前身份和政策、来源 Gate、完整扫描窗口与预算、当前物化状态、就绪和独立验证检查；缺配置必须保留 NOT_CONFIGURED。实际操作保存原始规范语义请求和服务端计划，历史读取按服务端固定的 Function 重新校验授权，不因目录新增候选而改写历史选择。

评估可通过既有 RESOLUTION 反馈、受审参考及回放协议复现；数据执行继续使用 DATA 参考。静态能力裁决、运行结局、数值回归和外部业务验收分别成立，不将任何一个升级为 Agent 的整体任务成功。

v3 模型修订继续进入 ADR-020 的受审替代链：旧、新请求的 metric 指针必须分别匹配执行时服务端固定的不可变发布，且为同 Metric 实体的更高版本；Function 也须保持同实体并提高版本。只有核实这些事实后，业务要求比较才忽略 metric/candidateFunction 版本指针；其他要求、政策、签名和原期望不变。跨指标、指标降级或混用旧消费协议拒绝，不能因 Function 版本更高就冒称同一任务。批准后的新实际回放负责替代验收，旧结果和失败仍保留。

## 证明边界与后续

这提供了正式需求到受限合法计划的真实纵切面，不是任意自然语言分析器。当前没有新增任意人群表达式、自由 SQL、通用工具循环、历史身份规则推断、SCD/AS_OF、单位换算、任意维度扩展、版本停用或全体消费者切换。原计划已有且已认证的输入关系仍须满足其运行约束，静态派生不能证明现实业务真值。

后续按真实域需求扩展正式算子和契约；身份、事件、账期和能力边界应继续落入系统可验证模型，不能退回 Prompt/Skill 硬逻辑。接口及限制见 [结构化需求指南](../../awe-registry/REQUIREMENTS.md)。
