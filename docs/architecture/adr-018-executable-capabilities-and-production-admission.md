# ADR-018：可执行语义、消费证据与生产准入

- 状态：已接受并实现受限工程范围；企业接入与领域业务验收独立进行
- 承接：ADR-013—017；M1/M2

## 问题与决策

语义登记、SQL 运行成功和人工批准都不能单独证明一次数据交付正确。模型要实际约束输入、计算、输出与实现；发现错误后，要按原问题和原权限范围重验；逻辑模型要能够先于物理表发布，然后通过现有工程平台完成物化并反馈实现证据。

保留七类模型，以严格 `schemaVersion: 3` 信封增加 `metricContract`、`datasetContract`、`pipelineContract`。v2 字节规范、Hash 和不可变发布不重写。跨 v2/v3 的模型升级必须显式遵循主版本兼容规则。

## 消费与语义边界

- Dataset 显式区分业务主体与输出行 Schema，区分观测来源和未物化逻辑目标。静态快照没有伪造的事件时间列。
- Metric 固定统计对象、身份空值策略、单位、时区、时间角色、输入读能力、类型化 IR、输出粒度及空集/除零语义。COUNT/SUM、分组、集合、窗口、比率及合法 Join 由同一类型系统约束；SQL 仅由已发布 IR 编译，拒绝调用方替换计划。
- IR 有节点、深度和运行预算。关联依赖正式 Link，实际检查唯一性/放大风险。AS_OF、多对多及未认证的复杂历史语义拒绝执行，不能用简化 Join 替代。IGNORE/REJECT 身份策略作用于已授权 Scan 输入总体；业务 Filter 不能掩盖 REJECT 违规。
- DataTask v1 EXTRACT 保持兼容，v2 QUERY_METRIC 增加正式指标消费。DIRECT 使用注册 BI 实现版本/Hash；可推导路径使用原生 PostgreSQL 只读事务。Hive/Spark 继续由既有平台适配，不伪装成 PostgreSQL 执行。
- OIDC 签名、issuer/audience、委托及有效期与服务端策略共同确定授权。字段、用途、实际展开的时间窗口和服务端行条件在每次扫描前生效，REST/MCP/回归共用同一入口。政策收紧后旧结果和诊断也不可读。

## 正确性证据必须分层

分开记录解析、授权、计划、来源、执行、就绪与验证。结构合法、账期到齐、独立数值对账、人工参考回归及业务验收不是同一种事实。

滚动窗口需证明所有实际输入窗口；静态源需证明实际快照。只证明结果日完整，不能认证过去六天输入完整。证明绑定模型/计划/政策/实现、操作、来源快照、run/attempt、时间和范围；逻辑来源还绑定确切物化与部署。缺少配置、未就绪、未知、无记录、0、NULL、NOT_APPLICABLE 分开，失败时不返回冒充完整的部分结果。

独立 checker 不接收待验行作为参考答案；它须提供绑定同一数据范围的独立参考。原生 PostgreSQL 事务快照 Hash 不能恢复历史数据；缺少真实同快照支撑时不能宣称对账通过。受审人工参考仅标记 `REVIEWED_REFERENCE_REGRESSION`。

## 知识与改进闭环

统一知识库提供授权后的正式能力、审定别名、领域覆盖、来源和不可变解析观测。模糊匹配需确认，多候选需消歧。未命中通常为 UNKNOWN；只有审定完整覆盖的正式命名空间内精确能力缺失，才可声明相应 MISSING，不能推断企业不存在该数据。

反馈区分用户声明、维护者归因、独立审核与回归证据。修复由外部团队/Agent/平台完成。AWE 重放相同数据义务，范围包含标准化请求、政策、模型/计划、物理绑定与实现；局部结果不能关闭更大范围问题。复发保留新发生记录。Agent 使用错误不能通过一次数据重验自动证明其整体任务已经修好。

## 生产准入与物化

Pipeline 固定输入读能力、逻辑输出、转换 IR 和所需 Contract。`AWE_PIPELINE_PLAN_V1` 是可验证加工制品；平台获取规范内容并独立观测真实制品字节。任意 SQL/脚本不享有通用等价性证明。

准入按以下链路运行：完整传递/共享物理资产影响 → 真实候选执行与独立回归 → 独立审核短期收据 → 平台在线一次消费 → 平台 CAS 发布 → 实际部署与输出元数据观测 → 绑定确切逻辑发布。

准入重新检查当前来源、制品、基线、影响、政策、套件、检查器及义务覆盖。不能只回传 PASSED。收据 Hash 不是离线部署权；平台必须在线消费并以 expectedBaselineRevision 做 CAS。AWE 不部署代码、不调度任务、不决定整个业务项目验收。

物化证据不改写逻辑发布 Hash。共享表的新制品取得写许可后，先封住旧物化证明；新部署即使 Schema 相同，也不能继续证明旧语义。查询与来源 Gate 必须使用确切实现证明。跨平台无原子事务，接入平台仍须保证受控写入、CAS 与可信运行观测；绕过这些接口的外部写入不能由元数据指纹证明语义未变。

## 验证与限制

真实 PostgreSQL/HTTP 集成测试覆盖类型化计算、BI 查询、独立对账、行权限、知识/反馈回放及实际建表物化后的查询，也覆盖错误制品、回归缺项、过期/陈旧批准、影响变化、并发消费、同 Schema 语义替换及旧证明失效。标准 CI 要求集成测试真正执行，不能跳过后显示成功。

这证明受支持 IR 与参考平台协议的工程链路，不能替代企业 IdP、Hive/Spark/BI、调度血缘接入、领域保留集、绕过入口治理、生产容量与业务验收。复杂语义按域需要扩展，不宣称 F4—F6 全部完成。不得把 M1/M2 参考验收写成全企业生产转型已完成。
