# ADR 总表：先固定的架构决策

状态：Proposed，需用真实数仓任务和领域负责人评审；不是最终上线许可。

## ADR-001 完整 AWE 产品，分开 Authoring 和 Serving

AWE 同时包含规范、建模页面、审核与发布、模型 Registry、语义规划与能力服务、Verification、Evaluation/Gap。两个工作流共享同一不可变发布模型，不再在 AWE 外另建一个“领域模型平台”。

对外延续现有统一知识库产品，AWE 是内部语义、能力裁决与受控消费内核；Authoring/Serving 是系统职责边界，不要求另建竞争的用户入口。成熟域已有资产优先采集、映射与对账，文档/搜索页面由同一权威定义投影。具体路线由 ADR-015 更新。

## ADR-002 三层模型，而不是万能 Entity

- 元模型：TypeDefinition、RelationType、OperationSignature、ValidationRule。
- 模型定义：业务对象/事件、事实、维度、指标、特征、Pipeline、DataProduct；领域负责、可发布。
- 物理与运行：Hive/BI/Topic/作业绑定，动态 Dataset Snapshot、Run、质量证据；权威保留在相应引擎。

业务对象 User Type 不等于用户表，更不等于单个 User 实例。YAML、UI 和自动生成都是同一模型的不同输入，发布必须走单一 Canonical Representation。

## ADR-003 语义模型与实现模型相互检查

在创建/变更表、SQL、任务时，同步编译或验证语义契约。模型粒度、身份、时间与物理实现不一致，必须明确失败或启动受审迁移。初期先绑定已有 BI/ETL，逐步迁移为统一权威，不强制一次替换现有生产系统。

## ADR-004 语义类型必须包含时间、身份、Grain 和聚合

时间角色：事件/业务/处理/系统/有效/可获得时间；模型快照、数据快照分离。关系含关联基数、桥接和 SCD 策略。指标按可加性约束。特征必须附历史观测/可用时点，以免信息泄漏。指标返回结果区分空、0、未到、无效。

## ADR-005 Resolver 是开放语言候选器，不是裁决器

自然语言 -> 领域候选、意图槽位（LLM 可选）-> 别名/术语/全文/向量/Graph 多路召回 -> 权威、类型、作用域和权限消歧 -> 已解析引用或要求澄清。禁止相似度代替业务定义；同名合法冲突需要命名空间和明确默认政策。

## ADR-006 组合推导是受限查询/加工规划

直接已认证能力优先；否则从现有数据、合法关联和算子寻找有界推导计划。类型化 Semantic IR 必须由服务端验证，Agent 提议不能直接执行。单次数据查询与需要持久数据加工的计划分开；后者属于正式开发、发布和审批工作流。成本上限、复杂度、超时和物理预算是合法性的部分。

## ADR-007 能力支持不等于结果就绪和已解决

至少保持五个正交事实：任务解析成功与否、能力直接/可推导/缺失/未知、访问权限、当前数据/工具就绪情况、验证证据充分性；外部 Agent 最终任务是否真正完成属于另一层结果。不要用一个 “可信成功率” 混淆。

## ADR-008 验证贯穿设计、发布、执行和反馈

验证包括：静态 Schema/Grain/时间/聚合/权限；代码/绑定漂移；执行与质量；独立复算/对账；业务抽审。治理 Certified 和证据 Verified 必须分开。证据有范围、快照和未验证事项。

## ADR-009 缺口事件不能等同于新知识需求

UNKNOWN 默认不派单。GapCandidate 需要上下文、失败的具体证明义务、候选归因和证据，经负责人确认后转为内容/模型/数据/工具/质量/Agent 工单。修复后以原任务和相关回归用例关闭；不能由 Agent 自动认证新的业务事实。

## ADR-010 联邦协作、唯一发布边界、可扩展适配

公共平台负责规范、Runtime、CI、Workbench；领域团队负责语义、实现绑定、业务验证；跨领域共享本体需明确权威和冲突。适配 BI、元数据、OpenLineage、调度和质量，使用已有工具而不重复建立数仓引擎。Java 21 + Maven + PostgreSQL + Spring Boot 模块化单体为初始部署方式。

既有知识库、平台/业务/个人 Agent 都通过相应发现与数据任务接口使用这些定义。现有平台的 MCP/API 可纳入 AWE 执行路径；未纳管直连和例外兜底需单独记录，不因工具存在就视为受控能力。

## ADR-011 安全与成本是编译前条件，不是后置过滤

MCP/API 必须鉴权；数据库/BI/调度服务端重新验权。受限 Link、行列/聚合权限、敏感特征及推理泄露要审查；资源预算、查询超时和并发上限是执行必要条件。写操作后置到 Action 能力且需要 dry-run、权限、审批、幂等、补偿、后验检查。

## ADR-012 不从模拟问数走向生产，改走可交付真实链路

保留实际类型、不可变版本、来源绑定与回归作为基础。根据 ADR-015，后续首先纳入成熟域已有资产，完成受控问数/取数、对账及阶段归因，再约束该域新增/变更并逐域推广；F3 的运行证据与反馈随消费链建设。F0—F6 是能力地图，不能成为推迟可信消费的全局串行门槛。不得把硬编码问题分类或 Mock 结果作为正式完成指标。
