# AWE — 方向性风险与不可违反的架构约束

## 目标与非目标

目标：传统数仓的数据建模、加工、质量与消费契约进入正式开发和运行流程；AI、BI、算法和数据开发工具共享已发布的、可检查的模型与能力。AWE 包含建模、Registry、规划、执行适配、验证、反馈和 Web 工作台。

非目标：重新造 Hive/Spark/Flink/调度、全面替代 BI、为每个实体启动 Agent、将数亿数据行装入知识图谱、证明企业数据绝对真实、从 LLM 文本直接执行生产写操作。

目标至少覆盖 F3：同一发布模型既进入数仓生产/变更 Gate，又由真实消费与检查任务引用；发现错误后能推动真实数据或实现修复，并以相同任务、版本和证明义务回放验收。当前的 PostgreSQL 只读契约检查是该闭环的第一个执行纵切面，不代表完整语义查询、生产作业接入或企业验收完成。

Agent 可以在自己的系统保存 Skills 并定制流程；AWE 提供受鉴权的稳定 API、版本模型和注册能力。调用方的 Skill 既不是新的业务权威，也不是任意 SQL/脚本的服务端执行许可。验证范围、缺少配置、数据不可用和执行未完成必须作为结构化事实返回，不能被 Agent 的成功叙述覆盖。详见 [ADR-014](adr-014-agent-skills-and-data-verification-loop.md)。

## 可能导致推倒重来的遗漏

| 风险 | 必须采用的设计 | 反例 |
|---|---|---|
| AWE 只是一层高级问数服务 | 语义契约必须进入数仓开发、发布和变更验证流程 | DWD 粒度改了，AWE 仍无感 |
| 语义与真实物理实现各一套口径 | 源系统权威边界、绑定、对账、漂移发现，逐步迁移权威 | BI 与 AWE 算 DAU 不同 |
| 模型不区分类型、定义和实例 | TypeDefinition、ModelDefinition、PhysicalBinding、RuntimeObservation 分离 | 数亿 User 实例写入 Registry |
| 忽视身份映射 | 用户、设备、游客、账号与历史映射为独立实体/规则 | 登录后同人双计 |
| 忽视 Grain/Join 基数 | 有类型的主键、关联角色、Cardinality、Bridge、Join Safety | 跨表扇出使收入翻倍 |
| 忽视度量代数 | additive、non-/semi-additive、distinct、ratio、time rollup | 7 天 DAU 求和冒充 WAU |
| 把时间当单个日期字段 | event/business/processing/valid/available/system time 各自存在 | 回补后的值泄漏到历史训练集 |
| 缺少数据状态语义 | ZERO、NO_RECORD、NOT_READY、INVALID、WITHHELD、UNKNOWN | 没到齐视作 0 |
| LLM 相似性当作业务等价 | 候选召回与权威绑定分离，歧义可拒绝 | 年龄=注册/实名/推断 |
| 目录找不到就断言不存在 | 覆盖范围声明，默认开放世界 UNKNOWN | 未接入的 BI 其实已有指标 |
| 可推导变成“随意 SQL” | 受限类型化算子、限定深度/预算、证明义务 | 不合法 JOIN 被当作新能力 |
| 数据认证被理解成真值证明 | 治理、语义一致、数据质量、独立证据分开 | 埋点丢失但 SQL 和 BI 一致 |
| 一个统一成功率覆盖全部 | 解析、供给、权限、就绪、验证、任务完成多轴 | “SQL 成功”冒充问题解决 |
| 只处理短任务 | Plan ID、持久化、重试、幂等、超时、补偿与跨系统状态 | 任务被中断后丢失结果证据 |
| 口径发布不带版本 | 原子发布、版本清单、内容 Hash、时点回放、影响传导 | 报表回放时使用新口径 |
| 部门间强行统一含义 | 命名空间、领域自治、跨域权威与冲突裁决 | 两个合法的新用户定义被合并 |
| 忽略安全与查询成本 | 源端二次鉴权、行列权限传播、受限关联、预算和资源限额 | Agent 大量扫描或跨权限重建敏感数据 |
| 算法特征等同普通指标 | point-in-time、available-at、TTL、online/offline、特征版本 | 训练/在线不一致与未来信息泄漏 |
| 内容维护额外填报 | 开发中自动抽取、变更 Gate、平台辅助建模 | 数开更改 SQL 但不更知识 |
| Gap 自动派单 | 区分缺知识/关系/数据/计算/权限/运行/Agent误用；审核、去重、回归 | 100 次同一错误创建 100 个工单 |

## 十个系统级不变量

1. 发布模型与 Plan 必须引用不可变 ReleaseID、语义 Hash，并记录物理绑定版本。
2. 解析结果是带来源的候选，LLM/向量分数不能直接认证业务等价。
3. 未知不是缺失；只有明确声明覆盖范围和失败证明，才允许产生 MISSING 候选。
4. 合法计算必须建立 Grain、身份、时间、聚合、关联、权限和资源约束。
5. 不允许隐式从精确口径降级到近似口径，不允许将日报去重值跨日求和。
6. 模型治理认证不等于独立业务真值认证，证据说明范围和遗漏。
7. 授权在服务端执行时重新判定，并在真实数据/调度系统再次执行。
8. 数据结果必须区分 0、没记录、未到、无效、无权限、未知。
9. 单次推导不自动产生正式业务指标或永久加工任务。
10. 模型或物理加工变更必须触发依赖影响分析和相应回归验证。

## 权威来源

AWE 发布的领域语义模型是目标权威；但现有 BI 指标实现迁移前，BI 为执行口径权威，AWE 以版本绑定引用并比对。物理 Schema 来自元数据系统；JobRun 来自调度/Flink；质量状态来自质量服务；知识文档来自现有知识产品；Trace 由现有 Langfuse/OTel 承载。AWE 保存引证、哈希、快照及证据，不复制所有动态运行状态。

## 行业参考（仅借鉴契约和模式，不默认引入代码）

Palantir Ontology：Object/Link/Action/Function 与模型实例分离。
AtScale SML：语义模型作为 Git/CI 中可发布代码。
Cube：统一语义、多接口消费、查询时权限和预聚合；严格 Join Path 校验。
dbt MetricFlow：实体键类型驱动安全关联，语义建模不替代上游数据加工。
ODCS：Schema、质量、SLA、Owner 的机器可读生产消费契约。
OpenLineage：Dataset/Job/Run + Facets 的可扩展工程血缘。
Feast：历史时点正确性、训练/在线一致性及特征可用时间。
Apache Iceberg：数据快照与版本演进是物理层能力，不能用语义版本代替。
