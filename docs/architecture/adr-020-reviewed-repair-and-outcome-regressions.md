# ADR-020：模型修复的受审替代与控制结局回归

- 状态：已接受并实现有界工程范围
- 承接：ADR-018/019；M1 的消费效果改进闭环

## 需要闭合的两个断点

原回归只重放同一固定请求/模型范围。数据行或别名修复可以重验，但修订正式模型后范围变化，缺少受审迁移；简单放宽 scope 会让别的任务或权限范围冒充修复。另一方面，系统虽会拒绝或返回未就绪，参考协议却主要表达成功数据值，无法独立验收正确拒绝。

## 保留旧证据，追加新期望

原 case、caseHash、审批、失败和精确范围校验不改写。新参考通过不可变 expectation facet 区分 DATA_RESULT、DATA_OUTCOME 和 RESOLUTION；旧 expectedState/expectedFingerprint 请求继续兼容，不能与新格式混用。

DATA_OUTCOME 精确比较操作状态、HTTP 状态、四个决策轴、失败发生阶段和 noDataReturned，不能使用空数组 Hash 或 0 代表正确拒绝。它只证明当前行为符合受审期望，不能作为数据修复闭合凭据，也不证明根因或整体任务成功。

## 受控真实观测

新增回归观测入口接收经过认证、格式正确的既有 DataTask 请求，共用原消费内核、权限、来源、预算和执行。前置业务拒绝可以形成带主体和政策的不可变观测；原数据 API 仍返回原来的 HTTP 403/404 等，不改为成功。未认证和请求语法错误不伪造业务观测。

观测不复制数据行，成功结果仍保存在原子操作及其独立 TTL 下；控制状态、固定模型、快照、结果 Hash 与子操作引用保留。幂等重试返回原观测，跨载荷或政策复用键冲突；没有终态不能作为回归锚点。进程崩溃留下 RUNNING 时不虚构自动恢复。

## 模型修订的替代验收

迁移对象显式连接旧反馈、旧受审参考和新受审参考。当前支持：同主体/政策、同 Function 实体的更高发布版本，原业务请求、时间、用途、字段、预算、强制行范围、输出签名及原结果期望保持一致。模型/物理绑定的差异由服务端从不可变观测生成，Reviewer 根据确切 migrationHash 审定。

批准不等于修复。批准后必须对新参考真实重放、匹配原期望，且晚于最新复发，才可记录 RESOLVED_BY_REPLACEMENT。它表示这个任务已接受新版本替代，不能声称旧固定版本已修好、两个模型普遍等价或旧消费者已完成切换。旧请求继续出现可使反馈重开，历史迁移显示 REOPENED/非当前有效。

政策扩大、换问题、换 Function 实体、改输出身份/单位/粒度或改原参考答案不属于本迁移；必须提出新的业务义务并独立治理。原同 scope 技术闭合仍有效，跨 scope 不能借新通过回放绕过。当前替代用于具体 MODEL_GAP 归因，不用数据证明关闭 Agent 使用问题。

## BI 来源投影与快照

不同查询快照不等于不同数据来源。管理员可为 BI 实现绑定 sourceProjectionRef，可信网关须按该请求准确证明，才可把多次快照归到同一正式来源投影。客户端不能自报投影，未注册、缺失或错投影拒绝；旧 opaque 句柄保持保守校验，不进行猜测性截断。

投影身份不提供历史恢复，也不代替同快照独立数值对账。受审参考回归继续标记 REVIEWED_REFERENCE_REGRESSION；只有实际独立 checker 的对账符合其协议，才能建立相应数值验证事实。

## 工程验收与后续

真实 PostgreSQL/HTTP 验证错误过滤模型修订、独立 SQL 参考、新回放替代、旧失败保留、复发、跨主体/范围/单位/政策/参考拒绝、并发幂等、不可变记录、真实拒绝和 BI 就绪状态切换，以及稳定 BI 投影下不同快照的数值回归。工作台分别显示观测、期望、审核、回放和替代验收。

这不代表 M1/M2 全面完成。结构化需求到合法计划、版本停用/消费者切换治理、存量 SQL 制品纳管、实际血缘覆盖及企业业务验收继续按路线推进；不将这些职责退回 Prompt/Skill 或另建 Agent 工作流。
