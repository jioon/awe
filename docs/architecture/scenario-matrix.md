## 成熟领域推广验收：D01—D12

本节是 [ADR-015](adr-015-domain-knowledge-and-controlled-consumption.md) 的目标验收契约，**不代表现有代码已执行或通过这些场景**。由首个成熟域负责人选定真实资产、任务、精确/近似规则、参考结果和数据版本；平台线下接入后验收。不能用更多静态知识条目或只读质量测试替代。

| ID | 场景 | 目标行为与必须保留的证据 |
|---|---|---|
| D01 | 已有指标的正式问数 | AWE 解析到明确口径、人口/过滤、单位、时间/时区和发布版本，复用受控 BI/指标等实现；与独立参考在相同范围对账，结果有模型/计划/来源/权限与验证引用 |
| D02 | 业务实体或明细取数 | 明确行粒度、字段类型与单位、时间/用途；执行行列权限、脱敏、行/字节/分页及导出限制；无记录、未就绪与 0 不混同，不接受任意 SQL 绕过 |
| D03 | 年龄、用户或同名指标有多个合法含义 | 返回授权范围内候选并要求澄清，或应用受审显式政策；记录选择依据，不能以向量相似度自动认证业务等价 |
| D04 | 授权范围内应可见模型存在，故意让检索未召回 | 通过受限内部 Trace 定位索引/过滤/召回发生点；合法权限过滤不作为召回缺陷；不自动新建重复知识或把它派成数仓缺数据问题 |
| D05 | 未完成覆盖的领域查不到资产 | 返回 UNKNOWN 及覆盖限制；只有已确认范围内的具名证明才能形成 MISSING 候选，不宣称企业不存在 |
| D06 | 每日 DAU 求七日去重，或无合法路径的关联 | 拒绝非法聚合/Join 并给出失败义务；存在合法明细时产生受限推导计划，否则说明缺口/未知；不改走自由 SQL/MCP 强行计算 |
| D07 | 分区未到、回补中、快照或来源不可用 | 就绪状态与能力供给分离；不返回 0 或隐式换旧数据/旧口径；重新执行或缓存复用需检查数据、策略、预算及版本有效条件 |
| D08 | 用户无权读取敏感字段或执行导出 | 发现、计划、执行和源端均守住权限；不能用备用共享高权限账户兜底，也不向无权用户泄露隐藏资产与完整诊断 |
| D09 | AWE 未支持，请求走既有 SQL/MCP 例外 | 独立授权、原因、责任、预算、来源和验证限制齐全；清楚标识未纳管部分，单独统计兜底；拒绝/歧义/非法计划不自动转例外 |
| D10 | 工具结果正确，Agent 最终叙述变更口径 | 获取最终回答及引用后定位为使用/解释问题，原数据证据不被篡改；未收到最终回答时任务完成保持未评估；新推断不继承原认证 |
| D11 | 已纳管域新增/变更实现，模型或旧消费者未同步 | 准入绑定候选版本、代码制品、策略与回归；发现传递依赖及共享物理资产上的旧版本消费者；错制品/过期批准/未覆盖回归不能发布 |
| D12 | Skill 硬逻辑或线上失败被定位并修复 | 业务口径/字段映射/聚合/时间/安全规则进入受审模型、算子或策略；用户流程保留外部；知识/检索/模型/数据/Agent 各归其责，原任务与受影响回归通过后由负责人接受 |

M0 建立任务与来源基线；M1 首先验收 D01—D10 及其对应 D12 反馈，M2 强制 D11 并补齐变更相关 D12。域内需要 SCD、比率、复杂 Join 或历史特征才能完成的任务，应提前实现相关 F4/F5 子能力，或明确排除并正确拒绝，不使用错误替代算法。

### 验收集与指标

- 领域负责人确认知识解释、数值问数、取数、歧义、权限、时效、非法计算和不可达等任务，开发例、独立保留例与线上观测分开管理。
- 每个指标的对账口径、数值容差、精确/近似、独立参考、时间与源数据版本明确；无参考时不声称数值正确。
- 所声明支持任务的正确完成、正确澄清/拒绝、支持覆盖、验证充分性分别统计；关键权限和非法计算反例必须正确处理，不能靠大量拒答抬高准确率。
- 每次失败有可复现的阶段与版本证据；根因可未知或多因，不强制归为知识缺口，不用补描述统一关闭。
- 跟踪 AWE 主链路使用、受控适配器执行、例外兜底原因/比例、未支持范围、权限/就绪违规、成本/延迟与请求预算、修复回归和实际维护成本。
- 资产数、向量召回率、SQL 成功率、单一“可信分数”以及 CI 绿色都不能单独作为成熟域上线标准。域内具体阈值随业务基线确定，不在缺少数据时编造目标数值。

## F1b 已实现的工程回归

| ID | 触发 | 必须验证的行为 |
|---|---|---|
| R01 | 七类元模型经工作台/API 发布 | 使用相同 Java 内核解码；未知字段、错误类型与不变量失败不能绕过提交/发布 |
| R02 | 旧 BusinessEntity 显式迁移 | 作者补全身份和类型并提高主版本；旧发布、Hash 与历史绑定不改写 |
| R03 | 来源未配置或不可达 | 明确 NOT_CONFIGURED/UNAVAILABLE，拒绝来源发布 Gate，不推断企业资产缺失 |
| R04 | 指纹匹配但字段、声明粒度、时间或 BI 定义错误 | CONTRACT_MISMATCH 阻断发布，失败事务后仍可查询证明记录 |
| R05 | Metric/Feature 引用已发布 Dataset | 固定版本/Hash，检查自身字段、主体、维度和历史时间，不能只检查 Dataset |
| R06 | 来源版本/Schema 漂移 | 保留新观测、聚合缺口候选及直接下游影响；只有重新检查恢复才标记来源问题恢复 |
| R07 | 破坏性模型变更、伪造证明或过期编辑 | 次版本破坏性变化、错误 Hash/快照范围、过期 revision 均拒绝 |

这些回归通过真实 PostgreSQL 和应用 HTTP 执行；来源网关使用显式协议 fixture。
它们不替代真实企业来源验收、数值对账、生产任务使用模型的证明或修复回放；后者继续按 S01—S20 的阶段门槛推进。
